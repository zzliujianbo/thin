# 内嵌 SSH：D 架构运行说明

这是当前选择的 SSH 入口；`sshd_config.thin` 和 `sshd-thin.service` 是旧外部 sshd 方案的历史样例，**不用于 D 方案**。本轮不安装、不启用服务，不更改系统 SSH/22、PAM、防火墙或 linger；以下仅为说明，不执行。

## 构建依赖

Linux x86_64、Zig 0.17.0、libc 与 libssh 开发头文件及共享库。初始适配环境是 Ubuntu 包 `libssh 0.10.6-2ubuntu0.5`，不是自行实现 SSH 或加密。动态链接需要部署环境提供兼容且持续安全更新的 `libssh.so.4`；版本/发行包升级应重新执行验收。

正常已有系统开发包时：

```sh
zig build -Doptimize=ReleaseSmall
zig build test-ssh       # Python 3 + OpenSSH 客户端；仅自有回环/临时密钥
```

构建机也可以只解包匹配开发 SDK，通过构建参数指定位置，无需安装全局包：

```sh
zig build -Dssh-include=/path/to/sdk/usr/include \
          -Dssh-library=/path/to/libssh.so.4
```

这些是构建选项，不是新的运行时 SSH 配置。运行程序没有依赖下载或自动安装逻辑。`install.sh` 仍只负责二进制，不负责系统依赖或服务。

## 启动

```sh
thin                                      # 原前台模式
thin --daemon                             # 只提供本机守护服务，不监听 TCP
thin --daemon --ssh-listen 127.0.0.1:2222   # 明确启用 SSH
thin --daemon --ssh-listen '[::1]:2222'     # IPv6，使用方括号
```

- 参数只能与 `--daemon` 使用；地址为数值 IPv4/IPv6，端口 1–65535，无隐式默认端口或 DNS 查询。
- 示例只绑定回环。对外地址、防火墙及服务持久运行仍需部署授权。
- 端口/密钥初始化失败时启动失败，不静默退回无 SSH 模式。
- `--connect`、`--attach` 和 `--resume` 不自动启动服务。

## 密钥与权限

- `~/.thin` 必须为本 UID 所有的私有目录（0700）；HOME 路径必须绝对、无符号链接，且 HOME 不可被组或其他用户写入。
- `~/.thin/authorized_keys`：用户手工放置公钥，0600、本 UID、普通文件、无硬链接/符号链接；最多 64 KiB、32 把 Ed25519 公钥。允许空行、注释和行尾说明，不接受 options、证书、其他算法或坏行。
- `~/.thin/ssh_host_ed25519_key`：独立服务器身份。仅当缺失时生成，0600，并以原子不覆盖方式发布。已有但损坏/不安全时拒绝启动，绝不自动替换。
- 客户端私钥仅留客户端；只将 `.pub` 内容加入授权名单。服务器主机密钥与登录公钥不是一回事。
- 每次公钥认证重新安全读取当前名单；删除 key 影响未来认证，不强踢既有连接。运行期文件坏掉只拒绝新认证，不取消已有任务。
- 主机指纹应通过可信渠道核对，客户端保留 known_hosts 固定身份，不用关闭主机密钥检查作为解决办法。

连接示例：

```sh
ssh -tt -p 2222 -i /path/to/client-key thin@127.0.0.1
```

协议用户名固定 `thin`，不要求同名 OS 用户，不使用密码/PAM/系统账户映射，也不读系统 SSH 配置。

## 进程与权限边界

```text
Thin daemon（监听 TCP、管理会话）
 ├── 连接进程：SSH 协议 + TUI，无服务端 PTY
 └── 会话工作进程：主 Runtime + subagents + 工具/后台命令
```

父进程只 accept 原始 socket，通过现有进程执行器的 stdin fd 交接与 exec 握手把连接交给独立子进程；父副本随启动握手关闭。SSH 状态在子进程中创建。内部入口不是公开远程命令接口，不能通过环境变量启用，也不会从客户端接受启动参数。

- SSH `pty-req` 只协商尺寸，不创建 OS PTY；`shell` 只启动固定 TUI，不启动登录 shell。
- 拒绝 SSH exec、SFTP、转发、agent/X11 及 env 注入。Thin 的 bash 工具仍能按现有权限规则执行命令：**TUI 不是沙箱**。
- 所有授权 key 共享 daemon UID 权限，不是多租户/角色隔离。
- 未完成终端初始化的连接最多同时 32 个；SSH 初始化 10 秒期限，父进程另有 15 秒交接保护。已就绪连接不占这个未认证池，无额外固定会话数量配额。
- 新连接遇到描述符、内存或启动资源不足时，只拒绝该连接并在后续轮次重试；执行器确认清理完成的启动失败不终止既有任务。只有实际无法确认子进程回收时，才按原有规则停止服务。
- 输出按序、有界，不丢弃部分帧；正常关闭发送退出状态、EOF、close，并有界排空。
- SSH 断开只回收连接视图；会话及已受理主任务/subagents 继续。subagent 在所属会话进程内并发，不是每个一个 OS 进程；工具启动的系统子进程是另一层。
- reconnect 后用户主动 `/attach`，允许重建 canonical 历史视图，绝不自动重放模型或工具请求。会话工作进程崩溃会影响其中主任务及 subagents。
- daemon 停止会取消和回收连接、会话、subagents 与所属后台命令；不承诺 daemon/机器崩溃后的任务连续执行。

## 服务托管

现有 `thin-daemon.service` 样例默认不打开 TCP。若后续获授权部署，可由管理员明确将其 ExecStart 改为带 `--ssh-listen` 的启动命令；不需要额外 sshd 实例。系统账户退出后是否继续运行由服务管理/cgroup/linger 策略决定，必须另做目标环境验收。

## 验证边界

`test-ssh` 使用实际产品 daemon 的同一监听端口、真实 OpenSSH 客户端、临时多公钥/主机身份和本机 mock 模型；不是先前 Python accept launcher 探针。结果以对应源码上的实际测试日志为准，编写测试不代表已通过。

测试还包含一个仅对自有 daemon 降低文件描述符上限的场景：任务运行期间制造慢握手准入压力，检查任务完成、请求不重放及资源释放后新连接恢复。这不是长时间大并发或慢读饱和验收。

正式发布仍需检查依赖版本安全更新、慢读背压/大并发资源行为、目标环境服务托管与公网配置。历史私有探针 9/9 不是本次产品回归或部署验收结论。
